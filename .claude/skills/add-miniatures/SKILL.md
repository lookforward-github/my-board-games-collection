# Миниатюры: реестр и картинки

Коробка (стартовый набор, набор юнита) — запись в `data/games.js` с
`kind: miniatures-item`; её заводит `add-game`. Здесь — то, что внутри:
каждая фигурка — запись в реестре `data/miniatures.js` и картинка в
`img/mini/`.

## 1. Разбери состав коробки

Состав — в `note` записи коробки или на странице товара издателя
(для StarCraft — archon-studio.com). Для каждой фигурки:
`node tools/catalog.mjs find <имя>` — если она уже есть в реестре,
просто увеличь `count`; новая — заводи запись.

## 2. Запись реестра

Общие поля — одинаковы для любой системы:

```json
{"id": "sc-goliath", "system": "starcraft-tmg", "title": "Голиаф", "originalTitle": "Goliath",
 "count": 1, "image": "img/mini/sc-goliath.webp", "starcraft-tmg": { ... }}
```

- `id` — `<префикс системы>-<имя латиницей>`; у StarCraft префикс `sc-`.
- `title` — русское название юнита как в русской локализации StarCraft
  (Зилот, Сталкер, Гидралиск, Морпех); `originalTitle` — английское.
- `hero: true` — у именных героев (Керриган, Зератул, Рейнор).
- `variantOf: "<id>"` — у альтернативной фигурки того же юнита
  (Преторианская гвардия → зилот, Тень адепта → адепт).
- `note` — что-то неочевидное: прозрачная фигурка-маркер, размер мата.

Всё специфичное для системы — в блоке с её именем. Для `starcraft-tmg`
посмотри 2–3 похожие записи того же типа (`faction`, `armySlot`) в
`data/miniatures.js` и повтори их набор полей: `faction`
(`terran`/`zerg`/`protoss`/`terrain`), `subFaction`, `armySlot`,
`combatRole`, `combatTags`, `baseDiameter`, `stats`, `combatScale`,
`cost`, `attacks`, `actions`, `upgrades`, `supplyProfile`. Источник —
официальные карты юнитов Archon (print-and-play листы
StarCraft-{Terran,Protoss,Zerg}-P2P-Card-Sheets на
starcraft-tmg.com/downloads). Террейн — только `{"faction": "terrain"}`.
Если карта юнита ещё не опубликована — заполни то, что известно, и
напиши об этом пользователю.

Новая **система** миниатюр (не StarCraft) требует правки `app.js`:
список фракций и их логотипы там заданы явно. Это не часть добавления —
скажи пользователю и остановись на записи коробки.

Записи добавляй тем же `node tools/catalog.mjs add <файл.json>`: объект
с `system` и без `kind` уходит в `data/miniatures.js`.

## 3. Картинка

Все картинки реестра — фото покрашенной фигурки без фона, вписанные в
прозрачный квадрат 720×720 с полем 19 px, WebP. Делает их скрипт:

```bash
tools/mini-image.sh <фото: файл или URL> <id> [допуск фона, по умолчанию 8%]
```

**Подбор фото.** Нужна одна фигурка целиком, спереди или в три
четверти, на однотонном светлом фоне, без коробки, карт и эффектов
выстрелов. Где искать:
- галерея товара на archon-studio.com: превью вида
  `/files/thumbs/Products/<папка>/<Имя> - N.jpg/732_732_crop.png` —
  оригинал без `/thumbs` и без хвоста:
  `/files/Products/<папка>/<Имя> - N.jpg` (2048 px). Перебери N = 1…8;
- страницы товара на starcraft-tmg.com и Gamefound;
- фото пользователя: можно попросить снять фигурку на листе белой бумаги.

Скачай кандидатов в scratchpad, собери из них контактный лист
(`magick a.jpg b.jpg -resize 300x300 +append sheet.png`) и посмотри его
через Read — выбери подходящее фото глазами. Фото с коробкой на заднем
плане или с фоном-диорамой не годятся: скрипт убирает только
однотонный фон. Если подходящего нет — спроси пользователя, не подставляй
неподходящее.

**Проверка.** Положи результат на яркий фон и посмотри:

```bash
magick img/mini/<id>.webp -background '#ff00ff' -flatten <scratchpad>/check.png
```

- остался светлый ореол или пятна фона — повтори с допуском выше (12%);
- пропали светлые детали (клинки, кристаллы, энергия) — ниже (5%);
- фигура по большей стороне должна занимать 682 px (скрипт печатает
  размер) — иначе на фото что-то лишнее попало в кадр.

Полупрозрачные эффекты на светлом фоне частично теряются при любом
допуске — если это заметно портит фигурку, покажи пользователю и
спроси, оставить ли.

## 4. Проверка

`node tools/catalog.mjs check <id фигурок>` — проверит, что у каждой
есть картинка на диске, система существует, а блок системы на месте.
