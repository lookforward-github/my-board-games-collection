# Добавление позиций в коллекцию

Каталог — статический сайт. Данные лежат в `data/games.js` (коробки) и
`data/miniatures.js` (реестр фигурок). Схема полей — `data/schema.md`,
правила и словари — раздел «Как добавить игру» в `README.md`. Прочитай
оба, если ещё не читал в этой сессии.

Инструменты (Node, без зависимостей; запускать из корня репозитория):

| Команда | Что делает |
|---|---|
| `node tools/catalog.mjs find <текст>` | есть ли уже такая позиция |
| `node tools/catalog.mjs vocab` | жанры, механики, издатели, системы НРИ — с частотой |
| `node tools/catalog.mjs add <file.json>` | дописать записи в конец файла данных в его формате |
| `node tools/catalog.mjs check <id> ...` | проверка каталога; переданные id — по строгим правилам и с отчётом «чего не хватает» |
| `node tools/bgg.mjs <bggId>` | данные игры с BoardGameGeek |
| `node tools/hobbygames.mjs search/product` | поиск, цена и обложка на hobbygames.ru |

## Порядок работы

1. **Разбери запрос.** Составь список позиций: название (как написал
   пользователь), ссылка, если есть, и предполагаемый `kind`:
   `base`, `expansion`, `tcg`, `accessory`, `rpg-supplement`,
   `miniatures-item`. Если пользователь указал язык издания, цену
   покупки или число экземпляров — запомни, это важнее найденного.

2. **Проверь дубли.** `node tools/catalog.mjs find <слова из названия>`
   по каждой позиции (и по русскому, и по оригинальному названию).
   Если позиция уже есть — не заводи вторую запись: спроси, это второй
   экземпляр (`copies` + 1) или другое издание (тогда `lang` массивом,
   см. README «Языки»).

3. **Собери данные.** Для каждой позиции выполни скилл `game-lookup`
   (загрузи его через Skill). Он вернёт готовый объект записи, источники
   и сомнения. Если позиций больше трёх — раздай их субагентам, по
   несколько на агента, и попроси каждого загрузить `game-lookup` и
   вернуть JSON; файлы данных субагенты не трогают.

4. **Миниатюры.** Если среди позиций есть набор миниатюр
   (`miniatures-item`) или пользователь перечисляет отдельные фигурки —
   после записи коробки выполни скилл `add-miniatures`: он заведёт
   фигурки в реестр и сделает для них картинки.

5. **Запиши.** Сложи готовые объекты массивом в JSON-файл в scratchpad
   и выполни `node tools/catalog.mjs add <файл>`. Дополнение пиши после
   своей базовой игры, если добавляешь обе сразу: `check` проверяет, что
   `parent` существует.

6. **Проверь.** `node tools/catalog.mjs check <id новых записей>`.
   - `✗` — ошибка: исправь запись в `data/games.js` и повтори проверку.
   - `⚠ не хватает …` — допустимо, только если данных не существует
     (у игры нет страницы на BGG, нет зарубежного издания). Тогда это
     должно быть объяснено в `note`, а для отсутствующего оригинала —
     стоять `"noOriginalTitle": true`. Иначе — дозаполни.

   Затем посмотри карточку глазами: запусти превью `site` из
   `.claude/launch.json` (локальный сервер на порту 8765; через
   `file://` скрипты не работают) и открой
   `http://localhost:8765/?game=<id>` — обложка должна загрузиться,
   параметры и цена отображаться. Сервер потом останови.

7. **Отчитайся** таблицей: позиция → id, тип, цена (₽ → $), источник
   цены и обложки, BGG-рейтинг/ранг, и отдельно — сомнения (неточное
   совпадение издания, цена не с Hobby Games, данные взяты у базовой
   игры).

8. **Коммит.** Закоммить изменения сообщением вида «Добавлена игра X»
   / «Добавлены: X, Y». **`git push` — только с согласия пользователя:**
   сайт публикуется на GitHub Pages из ветки `main`, пуш сразу выкатывает
   изменения на board-games.look-forward.ru.

## Правила, которые легко нарушить

- **Цена** — с hobbygames.ru, в рублях в `priceRub`, а в `price` —
  доллары по курсу **100 ₽/$**, округление до 5, минимум $5
  (`tools/hobbygames.mjs` считает это сам). Старые записи посчитаны по
  86.59 — их не пересчитывай без просьбы.
- Если пользователь назвал цену покупки — она главнее магазинной.
- Жанры (`categories`) — только из словаря (`catalog.mjs vocab`, первая
  строка). Новый жанр — только с согласия пользователя и с правкой
  словаря в README и `tools/catalog.mjs`.
- Механики — сначала из уже используемых (`vocab`), новые — только если
  подходящей нет.
- Не копируй сложность и время базовой игры в дополнение: у дополнения
  их нет (README, «Сложность и продолжительность требуются только у
  базовых игр»).
- id — латиница, цифры, дефисы; для дополнений — `<id базы>-<суффикс>`.
